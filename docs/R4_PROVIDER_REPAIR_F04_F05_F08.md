# R4 Etherscan provider repairs: F04, F05, F08

Status: **OFFLINE_CONTRACT_VERIFIED**. The adapter remains enabled. No real Etherscan request was made by this repair task and no historical ledger or raw response was changed. Live permissions and the cumulative 500-operation budget remain the access caller's responsibility.

F04 now reads raw amounts, positions, gas quantities and explicit statuses exactly. Decimal/hex nonnegative integer quantities retain arbitrary precision; float, boolean, negative, null or missing required amounts are not converted to zero. Missing or contradictory success flags yield an incomplete fetch. Internal success requires the nested call's own status; a successful parent transaction cannot establish it. Known failed transactions retain their fee information.

F05 validates known transaction, chain, block, block hash and transaction/log positions before filling missing locators. Receipt log identities must agree with the parent receipt and request. Missing redundant log identity fields inherit the already validated parent context. Identical Transfer amounts retain one event per distinct physical log index. Duplicate IDs, mismatched multiplicity, malformed logs or any identity conflict reject the transaction's enrichment and propagate explicit fetch gaps; they cannot leave a partially accepted enriched transaction. Receipt and fetch operation counters include failed requests.

F08 separates successful response caching from immutable failure attempt receipts. Stable read identities exclude run IDs and authentication. A claim is committed before budget reservation and dispatch; retries share a three-attempt lifetime across processes/restarts, retain retry_of and every old accounting entry, and respect persistent Retry-After deadlines. A live owner is never displaced just because its lease elapsed. Successful cached results need no transport. Timeout, temporary DNS, HTTP 408/429/selected 5xx and documented transient provider errors can recover; schema, authorization, entitlement and factual conflicts cannot trigger blind retries. The shared mechanism performs no network I/O or automatic risk release.

An old failed cache file alone cannot establish the number of previous attempts. It is indexed as HISTORICAL_ATTEMPT_COUNT_UNRESOLVED until complete evidence-backed attempt history is explicitly imported. Proven history persists through restart, and a previously exhausted chain stays exhausted. Original cache bytes are retained. Successful old cache bytes may be reused without a new dispatch or a new allowance.

The historical inventory checked 314 existing artifacts: 310 earlier-stage successful chain-evidence responses, two old synthetic cache artifacts, and two original Stage1B preflight URLError receipts with zero-byte responses. The preflight transport cause remains unresolved; these receipts are neither account-page success nor a reason to grant new attempts. No genuine legacy account-page failure cache was found in the declared search scope. Revision copies were excluded as duplicated evidence. All examined hashes were unchanged. This was a hash/status inventory, not a rerun of Stage0.

Validation on Windows 11 / Python 3.14.3: **63 tests passed**, comprising 20 shared-retry tests, 25 new provider tests and 18 original collector tests. Original F04/F05/F08 counterexamples were rerun against the immutable R3 source: all 9 defects reproduced. The same cases on R4 reproduce 0 defects; both positive controls pass. Linux was not tested by this subtask; final ZIP validation is recorded separately by the delivery validator.

The R4 version preserves that exact input as a rejection assertion, then removes only the locator in the positive control to verify legitimate enrichment and two equal-valued Transfer events. The immutable original source and original counterexample results remain available. No test was deleted or weakened.
