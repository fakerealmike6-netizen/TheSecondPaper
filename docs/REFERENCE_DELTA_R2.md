# R2 finite reference policy delta

`reference_delta_r2.py` replays only registered reference query slices that may depend on an actual changed frontier label. An address change can affect a registered target or act as a newly identified service along an existing registered certificate. Selection therefore includes queries for incidents whose already registered events touch a changed address, plus registered target rows involving the address. It makes no provider request, discovers no neighbor, and introduces no chain data or amount model.

For labels001, HTX and OKX identity changes affect 15 existing Harmony reference query slices containing 6,244 relation rows and 3,369 registered event rows. Replaying those same slices under the old R1 labels exactly reproduces the pinned old decisions (zero mismatches). Replaying under the new labels removes 81 downstream reference certificates under the existing first identified service rule: B2284→2203, C2272→2191, unresolved6473→6554. These are finite policy views; the final paper denominator remains unfrozen. No new actual tracing performance is claimed from this reference calculation.

The other 4,186 registered rows are not recomputed. Their original canonical row hashes and a minimal metric projection are included so the global counts can be reconstructed without embedding the full historical reference library. Included affected inputs contain only the necessary registered event/query/source rows and old/new identity slices. `affected_before.csv.gz`, `affected_after.csv.gz`, `affected_decision_delta.csv.gz`, and witness rows expose each affected decision. Original files are SHA-256 bound and remain unchanged.

`python src/reference_delta_r2.py verify --output derived/reference_delta_r2/labels_001` verifies the included payload hashes, replays both old and new affected decisions, and reconstructs global before/after metrics using the unchanged projection. It needs only the output tree and project source modules; it does not read the full original library. Verification passed locally on Windows Python3.14.3.

To incorporate later already-applied label batches, run the helper with the complete ordered `--label-manifests` list and a new output directory. It always compares against the original R1 reference baseline and the latest full label registry, preserving earlier output versions.
