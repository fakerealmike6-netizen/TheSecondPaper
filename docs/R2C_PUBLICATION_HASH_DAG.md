# R2C publication integrity DAG

`src/package_review_r2.py` operates on two separately prepared and reviewed input trees. It performs no source selection or copying, Git writes, network calls, account actions, or automatic private-data export. Historical trees and ZIPs are not rewritten. Existing generated files may be reused only when their bytes are already identical; a changed payload needs a fresh revision tree.

The generation order is:

```text
MIN payload + public payload
          -> shared PUBLIC_LOCAL_EQUIVALENCE.json
          -> each 12_FILE_HASHES.txt
          -> public ZIP + external sidecar
          -> fixed public commit / tag / Release verification
          -> external PUBLICATION_RECEIPT.json
          -> MIN ZIP, optionally including the publication receipt
          -> MIN external sidecar + external REVIEW_HANDOFF.md
```

The equivalence file binds only frozen payload bytes. It maps every public payload file to an identical local file, a documented sanitization difference, or an explicitly explained public-only file. Each mapped byte hash is recomputed during verification. A private-payload inventory commitment also detects changes in local-only evidence without publishing its individual paths. New or missing payload files invalidate the frozen mapping.

The equivalence object, file manifest, publication receipt, two ZIPs, sidecars and external handoff have explicit `EXCLUDED_FROM_PAYLOAD_EQUIVALENCE` records without a claimed final hash. Both file manifests exclude only themselves and `PUBLICATION_RECEIPT.json`, and document these exclusions in their headers. The late receipt may be added to MIN after manifest generation; it is bound by the final ZIP SHA-256. Final MIN size/hash is kept outside its own contents. In particular, the equivalence file never contains a stale hash of `12_FILE_HASHES.txt`.

The public tree must satisfy an explicit path allowlist and the retained R1 text scan. Source/tests, the known synthetic fixture directories, Markdown method documents, explicitly named public configurations and R2 aggregate reports are allowed. Private/raw/derived directories, the complete private R2 policy and publication receipt are refused in public. This bounded scan is a last check, not evidence that arbitrary third-party material is safe merely because it is renamed into a fixture path; the caller remains responsible for preparing original source, synthetic fixtures and sanitized reports.

Archive generation requires an already valid manifest, normalized unique regular files, bounded sizes, and no links/reparse points or runtime/Git directories. ZIP entries use fixed timestamps, UTF-8 names, compression settings and regular-file modes. The finished archive is CRC-checked and each entry is compared with its prepared input bytes, followed by a fresh manifest verification. Existing ZIPs are never overwritten. The public Git tree SHA-1 is computed from exactly the same bytes with file mode `100644`; actual Git publication must independently compare its commit tree to this value and avoid line-ending transformations.

Reports inside the frozen payload describe the publication protocol or status as of payload freeze. Later commit IDs, Release results and downloaded asset hashes belong in the external receipt/handoff; they are not backfilled into a committed payload to create another hash cycle. Remote publication success must come from actual remote verification, not from this local packager's return value.

Python API sequence:

```python
from package_review_r2 import (
    freeze_payloads, verify_equivalence, write_manifest, deterministic_zip,
    write_sidecar, git_tree_sha1,
)

# The caller has already prepared the two explicit input trees.
# Differences is keyed by public path. Set local_path=None only for a
# documented public-only file; omission means the same local path.
freeze_payloads(min_tree, public_tree, differences={
    "README.md": {"reason": "Public reuse instructions omit local evidence details."},
})
write_manifest(min_tree)
write_manifest(public_tree)
verify_equivalence(min_tree, public_tree)
public_binding = deterministic_zip(public_tree, public_zip, public=True)
write_sidecar(public_zip)
expected_commit_tree = git_tree_sha1(public_tree)

# The caller performs authorized publication and writes the external receipt.
# If the receipt is also included in MIN, insert it now under its explicit
# excluded name PUBLICATION_RECEIPT.json, then verify equivalence again.
verify_equivalence(min_tree, public_tree)
private_binding = deterministic_zip(min_tree, min_zip)
write_sidecar(min_zip)
```

The CLI exposes `freeze`, `verify-equivalence`, `manifest`, `verify-manifest`, `git-tree`, `zip`, and `sidecar`. `freeze --differences` accepts the documented-difference JSON. Use separate fresh paths for staging and final archives; no final actual packages are generated by unit tests.

Eleven synthetic tests pass on Windows/Python 3.14.3. They cover the late-receipt DAG, private aggregate commitment, explicit sanitization/public-only mappings, stale and incomplete mappings/manifests, preservation of frozen metadata, public path/content rejection, deterministic ZIPs, no overwrite, normalized path rejection, and an independently encoded Git tree. Final package validation and actual remote publication remain separate operations. External acceptance remains PENDING_REVIEW.
