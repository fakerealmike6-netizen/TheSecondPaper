# CONTROLLED_V1 construction and independent checks

This suite is a new, outcome-independent Stage1C synthetic development suite. It is not the historical twelve Stage1B scenarios and is not external blind ground truth. All 60 identities (six families, indices 0 through 9) were fixed by `PARAMETERS_AND_DESIGN.json` and `MANIFEST.json` before the method batch. No sample was filtered on endpoint, recall, feasibility result, or baseline performance.

`stage1c_controlled.py` constructs each physical chronological ledger and its source/normal decomposition using nonnegative exact integers. Each debit first reserves a feasible source share between `max(0,s-(b-v))` and `min(s,v)`, then updates both components. Gross protocol debit happens before refund. The two components sum to the observed flow. The generator never calls the primary LP or the Oracle. Hidden shares and complete actual balances for deliberately missing-information cases are saved only in `hidden.json`; methods receive only `observed.json`.

The frozen seed string is `TheSecondPaper/Stage1C/controlled-v1/<family>/<index>`, where index is an unpadded integer. Its UTF-8 SHA-256 digest is retained in the manifest. A draw hashes that digest concatenated with a four-byte unsigned big-endian counter starting at zero, interprets the first eight result bytes as an unsigned big-endian integer, and uses modulo mapping to the inclusive requested range. There is no environment randomness or retry. Parameter draws and hidden-ledger draws use separate instances of this documented deterministic byte source. First two instances per family use source amount and normal amount 2; the other instances draw source 3–8 and normal 2–7. Family/index determine all structural alternatives.

The six families cover: five forced-positive-lower and five zero-lower ordinary mixes; split/merge and shared targets; repeated service entries plus ordered returns and pre-seed transfers; native success/failure gas with background inflow and anchors, including token/native separation; ten closed 1:1 WETH components with sequential or split outputs; and two zero-hop, two no-reachable-service, and six missing-information controls. The missing cases retain hidden complete initial actual balances while withholding those values from every method. They do not supply initial source money. Known keys, including newly created WETH accounts, are explicitly initialized to zero.

Four WETH cases include a synthetic gross/refund envelope around a canonical net WETH deposit. The refund belongs to that explicitly synthetic envelope. The data and reports do not claim that `WETH9.deposit` itself refunds. All conversions satisfy `gross - refund = output`; no generic DEX or non-1:1 semantics enter this suite.

`stage1c_oracle.py` accepts only the observed graph. Its imports are Python standard-library collections, copying and combinatorics; it never imports or reads primary LP code, constraints, endpoints, or hidden files. Its separate interpreter derives actual pre-debit residual capacities and post-operation capacities. A chronological network has account/asset state arcs, actual-flow arcs, source injection, irreversible fee/boundary sinks, and gross/refund/output junctions. Only one source of Q units enters the network. 1:1 conversions preserve flow units across asset-state nodes. Integer successive shortest augmenting paths with exact integer Bellman–Ford costs find minimum and maximum values for each event, each address/asset group and each same-asset joint group.

Every supported operation is a unit-coefficient flow junction. The incidence matrix is totally unimodular and all capacities and supply are integers. Thus each bounded linear objective has an integral optimum, and these Oracle endpoints are also exact extrema of the continuous source-allocation set. This argument is specific to the frozen integer-capacity 1:1 domain; the Oracle explicitly rejects non-1:1 conversion. It is not a generic grid approximation for fractional swaps.

`enumerate_integer_allocations` is a third, direct operation-by-operation implementation. It enumerates possible source shares using available source and residual actual balance, then checks every post-event source balance and anchor. It builds no flow graph and uses no primary model. The first two samples from every family were fully enumerated: `TINY_ENUMERATION_CHECKS.json` retains all 12 checks, covering 100 event/address/joint objectives. All passed. Network integrality connects the exhaustive integer endpoints to the continuous extrema.

`SEMANTIC_COMPONENT_EQUIVALENCE.json` retains all ten WETH component checks and 35 whole-query weighted directions, including joint weights, unequal weights and signed weights where two outputs exist. The two tiny components also enumerate complete raw and folded boundary relations for every integer source input alpha from zero to gross. Raw equations are `g=r+d`, `m=d`, and `sum(y)=m`; folded equation is `sum(y)=g-r`. Projection `(g,r,d,m,y)->(g,r,y)` has inverse `d=m=sum(y)=g-r`, with the same nonnegative port capacities. This gives an algebraic continuous bijection for this closed 1:1 component, in addition to the recorded finite checks. It makes no claim about unsupported protocols or real-case source amounts.

Local Windows validation used the existing Python 3.14.3 runtime, standard-library `unittest`, and inherited `lp_model` only as a post-construction feasibility checker. The 83 tests passed. They include all 60 hidden-vector constraint checks, Oracle coverage, 12 complete tiny enumerations, manifest immutability, hidden independence, gas/asset separation, strict pre-refund funding, refusal of non-1:1 semantics, zero-hop/no-target separation, a shared-source conflict witness, and full tiny semantic boundary equality. An initial attempt to invoke pytest was not runnable because pytest is absent; no dependency was installed, and the tests were adapted to the project's existing unittest framework before these successful checks.

Algorithmic independence here means separate model construction, optimization implementation, and direct enumeration, all authored within the same development session. It does not mean a separate external author or independent blind review. External acceptance remains `PENDING_REVIEW`.
