# Independent Stage1C baseline implementation

Implementation: `src/stage1c_baselines.py`, version `stage1c-baselines-v1.0.0`.
Tests: `tests/test_stage1c_baselines.py` (30 local semantic and integration checks).

`run_baseline(observation_document, method_id)` accepts the inherited complete
ETH context document or the inherited controlled graph schema. It performs no
file reads, network activity, primary solver/model imports, or Oracle calls.
Every call constructs new local state. The runner attaches the frozen scope and
label identities to its output and separately checks the returned Haircut
allocation against the original primary model.

`observed_targets(document)` derives address--asset groups from legal entering
physical ports and frozen service identities. Generic graph diagnostic
objectives, including protocol input/output objectives, are not service labels.
Seed reception at a terminal is a valid zero-hop entry.

The three method implementations consume the same ordered physical observations:

- BOUNDED_REACHABILITY keeps persistent temporal account--asset reachability,
  with witnesses. It ignores physical balance capacities and source allocation
  coupling. Every amount field is null; physical capacity remains a separately
  labelled observed field.
- POISON uses the same temporal marking semantics, assigning actual capacity
  to marked ports as `nominal_raw`. It does not clear a mark when a balance
  anchor is zero. Identical address/event sets to bounded reachability are
  permitted and expected on many fixed graphs. Its nominal amount is not a
  feasible allocation or a certified LP bound.
- HAIRCUT maintains exact `Fraction` actual/source balances and uses
  `physical_debit * source_before / actual_before`. Gas is processed once at
  transaction start, prior to ordered value flows, and only in ETH. Gross
  protocol inputs are funded before refund/output credit. Multioutput ports
  share a single funded gross proportional allocation. The implemented
  cross-asset support is certified ETH/WETH 1:1 net conversion; arbitrary swaps
  are explicitly not applicable.

For complete ETH context, independently compiled event roles preserve all
modeled internal transfers, explicitly normal source-zero receipts, boundary
outflows, and unknown external returns. Only the frozen candidate service entry
groups are counted as service objectives. Service and fee sinks cannot fund the
outside pool.

Haircut computes the outside pool's actual starting balance using the full
observed order:

`B0 = max(0, max_prefix(unknown_return_amount - nonservice_boundary_exit_amount))`.

The pool starts with zero source. Each actual exit deposits its generated
Haircut source fraction; each unknown return withdraws proportionally. Outputs
include the exact chronological cumulative sequence, B0, explicit
`H_BMIN_BOUNDARY_V1` name, `is_observed_fact=false`, and whether a return actually
requires use of the convention. B0 is not inserted into the primary model.

A modeled account with unknown total actual balance cannot generate a unique
positive-source proportional withdrawal until a reliable aligned anchor makes
that balance known. Such an operation returns NOT_APPLICABLE with null
allocation/results and an explicit account/event reason. Source-zero withdrawal
from an unknown account is uniquely zero and may proceed. Invalid overdrafts,
contradictory anchors, unsupported fee timing, duplicated physical IDs, and
malformed source/target roles are errors, not zero allocations.

For a successful Haircut run, `allocation_raw` contains every original source
port, including fees and protocol input/refund/net/output ports. The runner may
then call `lift_hidden_allocation_for_audit` and `audit_vector` solely to check
this already constructed allocation. No validation result feeds back into
allocation generation. The internal audit also retains each debit's exact
before-state, fraction, final source balances, losses, conversion changes, and
per-asset conservation equalities. Cross-asset raw totals are never combined.

The local tests exercise temporal restrictions, normal-income handling, state
isolation, no hidden/file access, native gas separation, first-service stopping,
zero hop, no targets, repeated target entries, source exhaustion versus
persistent Poison, fractional raw allocation, gross/refund accounting,
multioutput funding, unknown balances, explicit Bmin, and both inherited model
checkers used after independent construction. Final retained experiment results
are generated by the frozen Stage1C runner; local smoke results are not selected
as the experiment batch.
